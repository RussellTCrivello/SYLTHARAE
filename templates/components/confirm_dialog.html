{# component: confirm_dialog purpose: One way to ask "are you sure?" before something irreversible. The component renders the question; it never performs the operation and never knows what the operation is. The page decides - and it says which action it is asking about, by id, so the dialog and the action registry agree on what is happening. inputs: id (required, stable), title, message, scope_label, scope, confirm_label, cancel_label, dangerous, typed_confirmation, action, confirmation_key outputs: none - the dialog returns an answer, never a result events: shown.bs.modal / hidden.bs.modal (Bootstrap), accept and cancel resolved by the runtime as a Promise states: normal, saving, error, unauthorized slots: scope line (runtime text, e.g. "27 files"), error line accessibility: role="dialog" aria-modal="true", labelled by its title and described by its message; focus moves to the dialog and returns to the control that opened it (Bootstrap's own focus handling); Escape cancels; the typed-confirmation field is a real labelled input, and the accept button stays disabled until it matches. third_party: Bootstrap 5 modal only. No other dependency. css: btn-action, btn-outline-secondary, btn-danger, btn-primary, alert, spinner-border - all from the stylesheet this project already ships. boundary: destructive actions ask through here, and the server still authorises the request that follows. This dialog is a courtesy to the operator, never a security control. #} {# Usage - the page renders the dialog once and asks it at runtime: {% from 'components/confirm_dialog.html' import confirm_dialog %} {{ confirm_dialog(id='confirmDialog', title=_('Delete these files?'), message=_('This permanently removes the selected records.'), confirm_label=_('Delete'), dangerous=True) }} const yes = await ConfirmDialog.request({ action: 'files.delete_selected', scope: '27 files', confirmLabel: 'Delete 27 Files', }); if (yes) { ...the page performs the operation... } A typed confirmation (`typed_confirmation='DELETE'`) is for operations where a mis-click is unacceptable; the runtime keeps the accept button disabled until the word is typed exactly. #} {%- macro confirm_dialog(id, title, message, scope_label=None, scope=None, confirm_label=None, cancel_label=None, dangerous=False, typed_confirmation=None, action=None, confirmation_key=None) -%}
